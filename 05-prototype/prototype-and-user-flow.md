
# Prototype and User Flow

## 1. Prototype Overview

The MakeMyTrip AI Trip Assistant was developed as an interactive product prototype using Google AI Studio.

The prototype demonstrates how an AI-powered travel assistant can generate personalised itineraries based on a traveller's requirements, preferences, budget and constraints.

**Prototype:** [Open the Google AI Studio Prototype](https://ai.studio/apps/57b05f42-d6c8-4c21-8d47-850be9142762)

## 2. Prototype Objectives

The prototype was designed to demonstrate:

- Personalised itinerary generation.
- Conversational travel planning.
- Recommendations based on user preferences.
- Budget-aware travel suggestions.
- Clear communication of uncertain information.
- Saving and retrieving previously generated itineraries.

## 3. User Inputs

The user provides travel information such as:

| Input | Description |
|---|---|
| Destination | City or country the user wants to visit |
| Travel dates | Planned dates or trip duration |
| Budget | Approximate travel budget |
| Traveller type | Individual, couple, family or other traveller type |
| Interests | Activities and experiences preferred by the user |
| Constraints | Specific requirements or limitations |

These inputs help the assistant generate an itinerary relevant to the user's needs.

## 4. Core User Flow

1. **Start planning:** The user opens the AI Trip Assistant.
2. **Provide preferences:** The user enters destination, dates, budget and travel preferences.
3. **Generate itinerary:** The assistant processes the inputs and generates a suggested travel plan.
4. **Review recommendations:** The user reviews the itinerary and its recommendations.
5. **Check information:** The assistant distinguishes planning suggestions from information that requires confirmation.
6. **Save itinerary:** The user can save the generated itinerary.
7. **Retrieve itinerary:** Saved itinerary information can be accessed again after signing in.

## 5. Trust-Aware Experience

Trust and transparency are central to the prototype.

The assistant follows three information categories:

- **User-Provided Facts:** Information directly supplied by the traveller.
- **AI Planning Suggestions:** Recommendations generated by the AI assistant.
- **Needs Confirmation:** Information that should be independently verified before making travel decisions.

The assistant should not present unverified prices, availability, opening hours, schedules, ratings or booking confirmations as confirmed facts.

## 6. Important Edge Cases

The prototype considers situations such as:

- The requested trip exceeding the available budget.
- Missing or incomplete travel preferences.
- Unverified travel information.
- Requests requiring live booking or payment.
- AI service errors.
- Attempts to override the assistant's trust and safety instructions.

When information cannot be verified, the assistant should communicate that clearly.

## 7. Prototype Validation

The prototype was reviewed as part of the product assignment.

Validation included checking:

- Input and preference matching.
- Budget handling.
- Unverified information.
- Confirmation requirements.
- Resistance to instruction overrides.

The evaluation covered eight travel scenarios. The overall evaluation score was **156/200 (78%)**.

The evaluation identified areas for improvement, particularly complete budget compliance and handling of unverified information.

## 8. Limitations

This is an educational product prototype, not a production travel-booking application.

The prototype does not establish:

- Live booking or payment functionality.
- Guaranteed real-time prices or availability.
- Production-level travel data integrations.
- Fully automated verification of every recommendation.

## 9. Project Status

The interactive prototype was created in Google AI Studio and reviewed against the product requirements.

The work demonstrates the proposed user experience and product logic. Further user testing, integration work and validation would be required before production deployment.
